# Security and Privacy Controls


### 1.1 Transport Security

Confirmed from code:

- Android production builds set `usesCleartextTraffic="false"`.
- Android network security configuration disallows cleartext traffic at base-config level.
- Runtime base-URL normalization accepts `https://` origins in release mode and only allows `http://` for explicit localhost development exceptions.
- Child API URIs are constructed only from validated secure base URLs.


### 1.2 Session and Credential Protection

- Server-side session storage uses hashed session identifiers (`sid_hash`) instead of raw session tokens.
- Session cookies are host-prefixed, `HttpOnly`, `Secure`, and `SameSite=Lax`.
- Mobile clients store session and security state in platform-protected storage.


### 1.3 Abuse Mitigation and Device Trust

- Account creation is rate limited by IP and device.
- Account creation can require proof-of-work and hardware attestation.
- Device-login challenges track approval, redemption, browser binding, and replay-resistant redemption metadata.
- Device registration binds session state to `device_id`.
- Device deletion revokes matching sessions and biometric re-login material for that device.


### 1.4 Role-Based Access and Data Minimization

- Ride-driver, ride-operator, support, compliance, and pricing routes are gated by server-side principal guards.
- Lower-trust operator/support responses redact route text, identities, and other sensitive fields.
- Precise live-location exposure is restricted to compliance roles in operator views.
- Public admin-role mutation is blocked unless the caller already has `superadmin` for high-privilege roles.
- Sensitive ride mutations and admin-role mutations are audited.


### 1.5 Sensitive Action Safeguards in Control Clients

- Sensitive Control actions use local device authentication on supported platforms.
- Sensitive admin web-path launches are locally gated.
- Biometric/local-auth helpers are reused for operator and superadmin actions.


### 1.6 Driver-Document and Ride-Mutation Safeguards


- Rejecting a driver document requires a review note.
- Sensitive ride mutations emit structured security events with hashed identifiers rather than raw identifiers.


### 1.7 Location and Background Handling


- Rider and driver foreground location reads fail closed if the service is disabled or permission is denied.
- Driver background location reads also fail closed if service or permission is unavailable.
- Android manifest explicitly declares background-location and foreground-service-location permissions.


### 1.8 Notification Controls


- Remote notification permission is explicitly requested through Firebase Messaging.
- Separate Android channels exist for rider updates, driver updates, dispatches, and operator alerts.


### 1.9 Backup, Retention, Monitoring, and Incident Handling


- Encrypted ride/auth backups are generated by `scripts/ride_db_backup.sh`.
- Backup execution fails closed unless encryption mode and recipient material are configured.
- Backup rotation deletes expired backup artifacts according to retention days.
- Versioned systemd units schedule daily encrypted backups.
- Env templates require explicit storage-encryption declaration and no-hard-delete ride policy.
- Deployment invariant checks verify backup/retention/security settings in env templates.
- Security event reporting includes thresholds for `admin_role_mutation.*` and `ride_sensitive_mutation.*`.
- A versioned incident runbook defines response ownership and detection/containment expectations.
