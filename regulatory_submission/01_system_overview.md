# System Overview

## 1. System Boundaries

- `Shamell Ride`, `Shamell Driver`, and `Shamell Control` Flutter client are implemented in `clients/shamell_flutter`.
- The primary backend in scope is the Rust BFF gateway in `services_rs/bff_gateway`.
- The BFF exposes identity/session routes, ride lifecycle routes, driver presence routes, operator routes, support routes, document-review routes, and admin-role routes.
- The authoritative persistent store evidenced for this scope is PostgreSQL, defined through `services_rs/bff_gateway/migrations/*.sql`.

## 2. Major Components

### Mobile Clients

- Rider-facing trip creation, live trip status, and support submission flows are present in the Flutter client and BFF route definitions.
- Driver-facing queue, presence, live location, trip state, and document submission flows are present in the Flutter client and BFF route definitions.
- Control-facing operator, support, compliance, and admin-role surfaces are present in Flutter code and BFF route definitions.

### Backend Service

- `services_rs/bff_gateway/src/main.rs` defines public routes for:
  - account creation and device login
  - biometric enrollment and biometric login
  - rider trip creation and trip tracking
  - driver presence, queue, status, and location updates
  - operator live board, roster, fleet, support queue, document queue, and pricing policy
  - admin-role read and mutation endpoints

### Persistent Stores

- PostgreSQL stores authoritative identity/session and ride-domain records.
- Mobile devices also persist scoped session and security state in platform-protected local stores.
- Encrypted backup artifacts are generated by repository-controlled scripts and systemd timers.


## 3. Third-Party Services and Libraries Relevant to Auth/Data


- Google Play Integrity is referenced as an attestation option in backend auth runtime configuration.
- Firebase Cloud Messaging is used by the Flutter client for notification permission and notification delivery setup.
- Mobile location and map-related libraries include `geolocator`, `geocoding`, `flutter_map`, and `maplibre_gl`.


## 4. Data Flows Relevant to Schema and Auth

### Account Creation

- The client requests an account-creation challenge.
- The BFF validates device-bound challenge material, rate limits the attempt, and can require proof-of-work and hardware attestation.
- On success, the BFF creates an account row, a session row, and a device-session row, then sets a secure host-only session cookie.

### Device Login

- The BFF supports device-login start, approval, and redemption through explicit challenge tables and route handlers.
- Browser binding, approval state, redemption state, expiry, and replay-resistant redemption metadata are persisted in PostgreSQL.

### Biometric Re-Login

- The client stores biometric material using stronger platform-protected storage on Apple platforms.
- Biometric login and enrollment call dedicated BFF endpoints and result in fresh session issuance.

### Ride Operations

- Ride requests, matching, assignment, arrival, trip start, trip progress, completion, cancellation, and tracking are represented in dedicated PostgreSQL tables.
- Driver presence and live trip state are stored separately from immutable tracking-event history.
- Driver onboarding records include document type, document number, reviewer identity, status, and review timing.
- Support-case records link a rider, an optional ride, support text, contact preference, and resolution metadata.

### Operator and Admin Access

- Control routes are protected by role-aware server-side guards.
- Sensitive operator responses are redacted for lower-trust roles.
- Public admin-role mutation is restricted so that `admin` and `superadmin` changes require a `superadmin` caller.
- The Control client adds local device-auth gates for sensitive operator and superadmin actions.

### Backup and Monitoring

- Repository-backed scripts generate encrypted ride/auth backups and rotate backup artifacts by retention period.
- Repository-backed scripts and runbooks define recurring security-event review and incident response handling.
